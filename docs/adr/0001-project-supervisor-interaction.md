# ADR 0001：项目单源码审计与主 Agent 开放对话

日期：2026-10-21。状态：接受（产品/架构决策，尚未实现全部能力）。

## 背景

交互讨论确定：创建项目即导入一份源码；快照为内部机制。用户一键完成四阶段图谱化分析后，从入口浏览局部调用关系，并由主 Agent 协调路径探索与审查。原型中预设的三种指令类型已被明确否决。

## 决策

1. 新项目绑定一份审计输入；另一份源码另建项目，名称/说明可编辑。保留旧多来源/多快照项目，不破坏既有 ID 和数据。
2. 默认传统工具串行执行代码图谱、安全语义/攻击面、候选路径、筛选评分四阶段；Agent 增强可选。
3. 主 Agent 接收自由对话，自主决定回答或 MCP 工具组合；前端/后端均不通过意图枚举或关键词映射替代模型决策。
4. 主 Agent 可通过领域工具协调子 Agent；宿主仍掌握进程、租约、权限、预算与并发。普通授权动作自动执行，需要额外授权的领域动作保留其关卡。
5. 同一后端领域服务供 REST / MCP / Runtime 适配复用；新增受认证项目 MCP 能力，不把现有只读 stdio 服务默认变成管理接口。
6. 人可通过会话、子任务消息及直接控制介入；消息应用与暂停/停止有明确回执、版本和恢复语义。
7. 新路径形成账本新版本，历史证据/报告保持固定；模型不能直接提升漏洞裁定。

## 后果

需补齐项目绑定、分析运行聚合、主 Agent 会话、MCP 项目能力和主子任务消息。现有 Pi / llm 路径运行时、插件、工作流、图服务、验证与报告复用，不整套重写。DeepSeek 为后续开发执行者，不因此替换部署运行时。
