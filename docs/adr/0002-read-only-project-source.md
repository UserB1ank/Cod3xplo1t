# ADR 0002：单项目只读源码与 500 MiB 提醒

日期：2026-10-25。状态：接受并实现。替代 ADR 0001 中“快照为内部机制”的新项目主流程。

项目导入一份源码，导入完成后目录与文件设为只读。正式 Joern 分析直接读取该目录；不生成源码 TAR、不生成逐文件摘要清单、不按内容生成版本，也不在分析前对源码做内容完整性验证。不提供代码更新、多版本审计入口；失败可以重试。

`repository.Manager.ImportSource` 的绑定身份来自代码源身份，内容变化不会生成另一个版本。目录上传只需相对路径、大小和文件内容，浏览器不计算逐文件摘要；旧客户端若主动提供摘要仍按其请求校验。路径、文件类型、链接、归档解码和展开限额继续检查，避免导入越界文件。

正式图谱化按目录中普通文件的总大小统计，500 MiB（524,288,000 字节）以内直接开始。超过时启动 API 返回 409 `source_size_confirmation_required` 和 `source_bytes`，不会保存计划、创建任务或调用插件。页面显示大小，取消即结束；确认后提交 `confirm_source_bytes`。该值必须等于服务器当前统计的大小，否则再次请求确认。确认是本次启动的资源决策，不是源码版本或完整性承诺。工作流与插件输入预算至少 500 MiB，并按实际总输入扩展，不再沿用 64/256 MiB 上限。

上传/展开和目录输入仍有 8 GiB 的部署资源上限，单文件 4 MiB、上传项数 10,000 等既有筛选限制保留。500 MiB 是图谱化提醒阈值，不是拒绝上限；Joern 的内存、超时和输出预算分别管理。

`codexploit/source-directory/v1` 使用 host 解析的目录绑定。目录路径只出现在私有进程 job 中，不写入计划、调用记录或 API；file-job/v2 和 SDK 对该输入执行目录遍历与大小检查，无源码内容哈希。兼容 ArtifactRef 中的 SHA256 字段是绑定标识摘要，不能解释为源码内容摘要。Joern 插件升为 2.2.0，默认工作流升为 2.1.0，旧清单和旧运行保留。随宿主重新编译的静态扫描器独立发布为 1.0.14，避免覆盖已有 1.0.13 包摘要导致升级启动冲突。

为保留现有图谱、任务、数据库外键及历史报告，旧字段名 `snapshot_id`、目录布局和持久化行继续作为内部 scope 关联键使用。这些字段不表示新项目有版本管理。已有项目直接复用原只读源码目录，忽略已有源码 TAR/清单是否完整；不自动删除历史产物。显式运行旧版 TAR 插件时仍使用旧适配路径，正式 Joern 流程不经过该路径。插件包与分析输出的验证机制不变。
