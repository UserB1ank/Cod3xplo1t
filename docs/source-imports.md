# 源码导入

新项目使用“一项目一份只读源码、一次审计”流程。导入成功后只保存源码目录，不创建内容版本、源码 TAR 或逐文件摘要清单；Joern 从目录直接分析，不校验源码内容完整性。代码更新需另建项目。内部旧字段名和旧项目兼容范围见 [ADR 0002](adr/0002-read-only-project-source.md)。

## 归档上传

支持 ZIP、TAR、TAR.GZ / TGZ。浏览器检查扩展名及 8 GiB 上传上限，服务端检查真实归档结构；展开总计最多 8 GiB、10,000 个条目，单文件最多 4 MiB、路径深度最多 32。ZIP64、分卷、加密包、RAR、7z 和特殊文件不支持，嵌套归档不自动展开。ZIP 目录预算在分配条目列表前检查；TAR 终止块、ZIP/gzip 解码 CRC 属于归档格式检查。

默认过滤版本库、生成目录、平台附加元数据和明确敏感文件类型。拒绝绝对路径、父目录穿越、反斜杠、盘符、重名、文件目录冲突、链接和特殊文件，不继承归档所有者和权限。若只有一个外层包装目录，移除该层。保存后目录和文件设为只读。

原始归档只保存在私有暂存目录，成功、失败、取消后清理；启动时清理过期导入遗留。每实例同时处理一份上传，并发返回 429；处理期限为两分钟。上传和展开使用有界流，不把完整归档读入浏览器 JavaScript 内存。

## 浏览器目录上传

目录选择器先过滤相对路径并统计数量和大小，不读取所有文件计算 SHA-256。使用同一认证接口的 `format=directory`，multipart 的第一个 `manifest` 部分包含 `{files:[{path,size,sha256:""}],excluded:[path]}`；其后各个 `files` 部分携带文件内容。`sha256` 也可省略；仅旧客户端主动提供非空摘要时校验该文件摘要。

所选外层目录名和本机绝对路径不发送，内部层级、中文和空格保留。服务端检查相对路径、缺失/额外文件、声明大小、路径冲突及上述展开限额；清单最多 4 MiB，multipart 总计最多 8 GiB + 64 MiB 协议开销。目录中的单个子目录不会移除。导入报告中的摘要是排序后规范清单的标识，不是源码完整性保证；重试不依赖随机 multipart boundary。排除记录最多保存 200 项。

## 认证 API 与存储

`POST /api/v1/projects/{project_id}/imports/{source_id}?name=源码&format=zip|tar|tar.gz|directory` 需要 writer 权限。`source_id` 由调用者生成，相同导入标识可重试；项目已绑定就绪源码后不提供替换或新建版本操作。失败保留项目并允许重试。

返回值保留既有 `snapshot`、`source_id`、`source_version` 字段，以兼容图谱、任务及数据库关联；这些字段不表示新项目仍有快照版本功能。项目 sources 目录提供导入格式、数量、排除记录等信息，源码目录不会自动登记到产物库。

## 图谱化预算

开始前按源码目录中的普通文件总大小统计。≤500 MiB 直接开始；超过时返回 409 `source_size_confirmation_required`、`source_bytes` 和 `threshold_bytes`，不创建分析工作。页面显示实际大小并询问是否继续，取消不重试；确认提交 `confirm_source_bytes`。编译计划及插件输入预算按实际输入扩展，不能再被 64/256 MiB 默认值拦截。8 GiB 是部署资源上限；Joern 内存、超时和输出预算分别执行。

已有项目复用原只读目录，源码 TAR/清单的缺失或损坏不阻断正式 Joern 分析。旧历史产物不自动删除；显式运行旧版 TAR 插件仍保留旧适配路径。分析输出与插件包继续独立验证。
