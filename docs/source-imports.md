# 浏览器源码导入

创建项目时可选择本地源码压缩包、电脑目录或远程 Git 仓库；已有项目的“代码源 → 添加代码源”也支持相同入口。原先部署侧登记的 `/repos/...` 只读目录仍可使用。上传不会执行仓库代码。

支持 ZIP、TAR、TAR.GZ / TGZ；浏览器先检查扩展名和 64 MiB 上传限额，服务端独立检查真实归档结构。ZIP64、分卷、加密包、RAR、7z 和特殊文件不支持。展开最多 128 MiB、10000 个归档条目，单文件最多 4 MiB、路径深度最多 32。ZIP 目录在标准库分配文件列表之前检查条目预算；TAR 校验终止块，gzip 校验尾部 CRC。嵌套压缩包不自动展开。

页面显示实际操作阶段与不定进度条，取消会中止网络请求。请求最多处理两分钟，每个应用实例同时接收一份归档；并发超额返回 429。上传、展开与快照处理都使用有界流，不把完整归档放入前端 JavaScript 内存。

默认排除版本库元数据、生成目录、Mac 附加元数据和明确敏感类型（如环境文件、私钥文件）。这不等于识别所有源码中的秘密。原始归档只存在于私有临时目录中，成功 / 失败 / 取消后删除；发布产物仅包含筛选后的冻结源码。代码源详情保留原始上传大小、格式、SHA-256、展开文件数、排除总数与最多 200 条排除记录。快照阶段对二进制等文件的进一步省略另行记录。

部署使用的 `/tmp` 为 tmpfs，容器重启清除强制中断遗留的暂存。原生服务启动时有界清理超过一小时的上传暂存目录，保留新目录与无关文件；清理未完成时明确记录警告。该宽限大于正常上传的两分钟期限。

源码包若只有一个外层包装目录，则确定性地移除这一层；多根目录保持共同根。拒绝绝对路径、父目录穿越、反斜杠 / 盘符、大小写重名、文件目录冲突、链接和特殊文件，归档权限与所有者不继承。源码只有在校验完毕后才进入快照流程。

## 认证 HTTP 接口

`POST /api/v1/projects/{project_id}/imports/{source_id}?name={display_name}&format=zip|tar|tar.gz&build_graph=true|false&build_asg=true|false`

- 需要项目写权限；请求体是原始归档二进制，不经过 JSON 编码。Cookie 登录沿用同源校验，Bearer 登录沿用现有角色规则。
- `source_id` 是调用者生成的稳定 ID。相同 ID 和归档摘要可安全重试；不同摘要或其他项目已占用的 ID 返回 409。页面失败后保留已创建项目，重试不再创建重复项目。
- 返回既有 snapshot 响应，含 `source_id` / `source_version`、真实快照、可选图谱与识别结果。完整代码源和排除记录由项目 `sources` 目录读取，符合公共 `source.schema.json`。
- 来源类型为 `uploaded_archive`，位置为不可变逻辑引用 `upload:<sha256>`；不包含浏览器绝对路径或服务端暂存路径。Memory / SQLite / PostgreSQL 使用同一文档。
- 400 表示无效归档 / 参数，413 表示预算超限，429 表示实例繁忙。建图等后续阶段失败明确返回错误；已经建立的项目或有效输入可在正式页面查看并重试，不把上传成功显示成分析成功。

导入得到的快照与任务沿用现有持久化和产物存储。后续电脑目录变化不影响旧任务；重新上传使用新的来源 ID 和快照。已有上传来源只能重读其固定快照；快照被主动删除后需要重新上传，不读取浏览器电脑。

## 选择电脑目录

Mac Safari / Chrome 等支持 `webkitdirectory` 的浏览器可直接选择目录，不支持时页面提示使用压缩包。空目录和全部排除的选择明确报错。目录预检逐个读取最多 4 MiB 的文件计算 SHA-256，保留文件句柄，不把整棵目录复制进 JavaScript 内存。上传前显示保留文件数、总大小、排除数和前 200 条排除路径。明确敏感文件、版本库和生成目录在传输前排除；文件名过滤不能保证识别源码中的所有秘密。

目录使用同一认证接口的 `format=directory`，请求体为浏览器生成的 `multipart/form-data`：第一个 `manifest` 文本部分是 `{files:[{path,size,sha256}],excluded:[path]}`，后续每个 `files` 部分的 filename 为清单中的相对路径。所选外层目录名称、宿主绝对路径不发送；内部层级、中文和空格保留。服务端再校验清单、路径冲突、10000 项 / 128 MiB / 单文件 4 MiB 限额和全部实际内容摘要，拒绝缺失、额外、重复、变化和越界文件。清单最多 4 MiB，整个 multipart 请求最多 192 MiB，处理期限与归档相同。

来源类型为 `uploaded_directory`，格式为 `directory`，`import.bytes` 记录清单中实际传输的文件总大小；`import.sha256` 为排序后的规范清单摘要。排除项也参与摘要；随机 multipart boundary 和枚举顺序不会影响重试幂等。目录内部的单一子目录不会像归档包装层那样移除。

摘要校验固定本次读取并上传的字节；浏览器目录 API 不提供文件系统原子快照，读取期间请勿修改文件，发生读取错误或内容变化必须重新选择。后续修改再次上传产生新快照，旧任务继续使用旧输入。本入口无需 Docker socket 或动态挂载；宿主连接器仍是另行批准的可选方案。
