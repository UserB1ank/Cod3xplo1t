## 已确认偏差与建议修正

### 1. 项目入口仍落到旧任务页

`web/src/App.tsx:470` 的项目卡片onOpen默认view为tasks，只有creationTarget等其他上下文才可能走不同入口。新创建普通项目路径在861行已正确进overview，但再次从目录打开项目又回旧任务列表。

应统一“创建完成/打开项目/恢复项目深链接”的默认入口为项目总览，保留显式目标路由和旧深链接。此为#63主流程缺口，不能由API创建成功替代验收。

### 2. 查看审查路径按钮跳到任务列表

`web/src/ProjectHome.tsx:385` 和429行都把“审查路径”导航到tasks。实际支持勾选路径的界面在`Knowledge.tsx`的paths图层；当前nav没有独立审查路径入口。用户点击看到的是旧任务表，未进入路径筛选→审查的流程。

应提供独立审查路径路由/页面（或带明确paths子路由的既有组件），将两处入口接到真实路径清单，并用组件/路由交互及浏览器测试核实。#64/#65接线不能只测后端输出。

### 3. 局部图谱仍是关系列表

`web/src/Knowledge.tsx:1029`“相邻节点”和1058行“关系与证据”均渲染列表；没有原型的节点/边图形布局。新增查询有真实数据，但邻居/边列表不能替代已确认的入口局部调用图体验。

应保留当前有界查询、来源、源码抽屉，补默认1–2跳的节点连线图、模块聚合、选中/展开、深度/截断提示和可访问列表替代视图。#65应补图形视图验收，不是继续称局部图谱已完整对齐。

### 4. 主导航与工作台布局未采用原型主结构

`web/src/App.tsx:311`仍是项目概览、项目助手、挖掘任务、代码源、共享知识图谱等11项；原型主线是项目总览、代码图谱、审查路径、Agent工作台、发现与证据、报告，高级插件/工作流/输入详情另入口兼容。`web/src/styles.css:1`保持旧深色视觉；`Assistant.tsx:147`及styles.css:3356为聊天+固定信息两区布局。

应先统一导航/路由、标题、总览入口和主Agent工作台框架，再把现有真实服务接入；无需复制原型模拟数据。左侧子任务面板、消息回执和全局控制的真实能力属于仍开放的#68/#69，不把这些未开发项混成#66回归。但框架和命名不应继续向“独立项目助手附加页”分叉。

### 5. 主Agent运行时与原计划存在偏离

`internal/supervisor/supervisor.go:133`固定Runtime为llm，220行直接循环调用llm.Complete；`docs/supervisor.md`把Pi主会话适配留作后续。#66原规格要求复用已有Pi/llm工具桥及宿主描述/校验；当前是新的独立会话循环。

需核对并收口共享runtime/tool gate/预算策略，明确已有机制的复用边界与未交付项，不能无对应验收地把Pi或共享控制延后。这不是要求把主会话伪装成AuditPath；独立会话身份是正确方向。

### 6. 完成记录超出了已完成验收证据

AGENTS.md的#63–#66记录承认internal/app WIP、格式检查阻塞，#66承认未做真实模型验收而以合成provider替代。部分阻塞源于此前既有工作，不认定为这六个提交引入；但已关闭Issue不能因此视为通过完整交付总闸。

应将功能提交、原型对照、真实模型/执行器验收、仓库总闸分别记录。合成provider能证明协议链路，不能独自证明真实模型自主选工具；页面“能打开”不能证明符合原型。
