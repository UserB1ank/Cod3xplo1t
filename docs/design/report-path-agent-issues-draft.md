## 报告模板取舍

参考 `code-audit-system/templates/summary-report-template.md`、`vulnerability-report-template.md` 和 `per-vulnerability-verification-report-template.md` 的结构：项目概览、执行摘要、关键发现、验证结果、修复建议；单项包含摘要、影响条件、根因、源码位置、输入到敏感操作的证据、验证和修复。

只采用阅读结构与中文表达。模板中的样例漏洞、联系信息、漏洞编号、评分和复现代码不能进入真实报告。调用关系、静态污点流、模型审查与动态验证必须分别表述；缺失材料标记“未记录”“未评估”或“未验证”。不以严重性阈值隐藏已有发现，不因模板措辞将候选提升为已确认。

建议总报告目录：

1. 项目与审计范围：代码基线、固定知识版本、报告采集时间。
2. 执行摘要：已确认问题、待验证候选、路径审查进展和主要阻碍。
3. 关键发现与审查摘要：精简表格与稳定详情引用。
4. 覆盖与局限：去重汇总，说明影响，不重复铺满每条路径。
5. 下一步建议：与未决事项对应。
6. 证据与明细目录：认证下载入口及完整性信息。

## R1：生成精简中文总报告并在正式页面排版阅读

### What to build

**类型：AFK。用户故事：US1。**

从项目或任务的正式报告入口，基于固定输入生成可直接阅读的中文总报告。采用上述摘要模板，先给结论、进展与重要限制，再提供明细和证据入口。Markdown 用于人工阅读，完整结构化记录通过单独的不可变 JSON 产物保存；SARIF 的既有机器消费能力保持兼容。

模板、语言和中文展示材料固定版本。需要将历史外文内容转换为中文时，保存对应原文引用与中文展示稿，计入预算并记录生成来源；之后预览、下载与重新渲染不再次调用模型或读取最新裁定。不得通过仅翻译标题、隐藏英文结论或截断尾部冒充完成。

### Acceptance criteria

- [ ] 正式项目/任务入口生成、保存、预览和认证下载贯通；正文按中文目录表达，非中文业务段落有中文展示稿。中文生成不可用或失败时保留真实错误，不返回英文成功报告。
- [ ] Markdown 正文不嵌入完整 `capture` JSON，不逐路径重复相同局限；候选和未审查路径以统计、分组及明细入口表达，统计分母和排除策略清楚。
- [ ] 使用现有 termcp 报告的固定输入作回归：100 条候选、1 次审查、0 条发现的人工阅读正文不超过 30 KiB，能直接读出“存在未审查路径、该次审查证据不足、没有已确认漏洞”；不能写成全项目审计完成。此体积是该样本的验收预算，大项目通过分页或分册保存全部明细，不静默丢失记录。
- [ ] 正式预览支持标题、段落、表格、代码、目录和安全链接；不再只显示 Markdown 源码。脚本和原始 HTML 不执行，超大附件有明确独立入口，预览和下载来自同一已校验产物。
- [ ] 完整固定输入与机器证据独立保存，报告携带模板/语言版本、来源、大小和摘要；所有引用可认证读取并核对 SHA-256，原有候选策略和状态统计不改变。
- [ ] 旧报告字节和摘要保持不变；中文报告产生新版本。同一已保存输入及中文展示稿重复渲染字节一致，服务重启后内容一致，不能因最新图谱或裁定变化而变动。
- [ ] 覆盖无发现、有候选、证据不足、已确认、部分覆盖、分页及失败场景；完成真实 PG/API 和浏览器“生成 → 阅读 → 下载 → 重启复核”验收，记录改造前后字节数。

### 实现切入点

`internal/reporting`、`internal/verify` 报告渲染、报告公开契约、ArtifactStore、`web/src/Reports.tsx` 与报告客户端；报告版本按现有不可变插件规则演进。

### Blocked by

无，可立即开始。与 #48/#36 的后续数据扩展兼容，不重新实现其领域功能。

## R2：按中文审计模板阅读单项审查与漏洞证据

### What to build

**类型：AFK。用户故事：US2。**

从中文总报告或正式发现详情进入一项审查/发现的中文详情，并可下载该项固定报告。参考 `code-audit-system` 的单漏洞与验证模板，将当前已有答案、义务、源码和证据组织为人能理解的事实链；普通路径审查也能阅读，不强行为每条审查创建漏洞。

### Acceptance criteria

- [ ] 单项包含中文标题、一句话结论、影响与前提、根因、真实文件与行号、路径证据、安全控制、验证状态、支持/反对/未决证据、修复或下一步建议；未记录的字段明确说明，零值不伪装成有效位置。
- [ ] 静态调用、污点证据、模型判断、平台验证分别标识；保留候选、已确认、排除、证据不足与验证受阻的语义。未知 CVSS、漏洞编号、受影响版本或复现结果不自动补全。
- [ ] 新审查的人类可读结论以中文生成并沿现有答案校验保存；历史英文结论通过固定中文展示稿阅读，原答案、义务判定、证据 ID 和裁定保持原样，翻译不新增事实或提高确定性。
- [ ] 源码节选取自该项固定快照，标注真实位置和上下文范围；无法解析引用时明确“位置未解析”，不输出 `:0` 冒充证据，不借用最新源码填补旧报告。
- [ ] 有真实复现材料时给出环境、步骤、预期与实际现象及引用；没有执行验证时只写待验证条件与建议，不生成“已复现”的步骤或运行结果。当前不新增执行器。
- [ ] 总报告到单项、单项到证据/源码以及返回列表均可定位；导出与预览引用同一版本，完整性失败、归属不符和证据缺失返回真实状态。
- [ ] 用已保存 termcp 审查验证中文“证据不足”详情，再用确定性的已有验证数据覆盖确认、排除、受阻等分支；经过真实 PG 重启和浏览器阅读/下载验收，不要求真实项目必须发现漏洞才算通过。

R1 的固定中文报告模型、`internal/reporting/capture.go`、现有发现/证据与答案查询、正式报告和发现详情页面。需要的详情契约按现有身份映射扩展，不按标题关联。
