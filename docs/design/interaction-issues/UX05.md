## What to build

**类型：AFK。用户故事：** 对主 Agent 说“看看还有哪些入口可能遗漏”，模型自己选择查询/阅读/提交路径工具；新增路径出现在同一个项目清单，能查看依据并选择审查。

开放有界的项目路径提交 MCP 能力，复用正式路径/Normalizer/评分/观察服务。每条新路径携带真实 canonical 引用、知识视图、发现会话/工具调用、推断等级及与原路径的关联；工具决定验证与登记，不由模型直接写图数据库。

## Acceptance criteria

- [ ] 从开放对话经模型自主选择图查询/源码工具，随后提交真实候选；不是前端“新增路径”命令、固定三步或预设两个样例。
- [ ] 校验端点/边/源码证据属于同一项目输入和固定视图；实际调用可达与未证明连接分别标为 supported/hypothesis，不伪造边、不把假设提升为 dataflow/verified。
- [ ] 重复工具调用、并发提案、重启重放按稳定身份/请求幂等去重；保留多个发现来源，不按标题合并，不覆盖工具原始事实。
- [ ] 项目路径目录、总览数量、来源筛选、图谱入口和证据抽屉读取真实新增路径；每条可追溯到主 Agent 会话、工具调用、证据和评分版本。
- [ ] 自动审查策略由宿主授权/版本控制；默认新增候选等待人选择。超出路径数量、探索预算、范围或来源校验时明确拒绝并向模型回传原因。
- [ ] 产生路径目录/账本修订事件供 #47 消费，不能静默扩大已冻结 coverage_contract；不在本单重写覆盖判定或报告引擎。
- [ ] 真实 MCP + PG 端到端、重复/跨项目/失效视图/缺证据/上限/取消迟到提案/重启测试和真实模型探索的正式页面验收通过。

## 实现切入点

复用知识 pin、`internal/path`、`internal/plugin` Normalizer、发布和发现来源；根据已有路径身份算法设计新的发现 observation，而不是临时 UUID/标题去重。MCP 名称实施时注册，原型点分工具名不是协议承诺。

## 实施与交付约束

- 按 2026-10-21 已确认原型：一个新项目对应一份源码的一次审计；快照在创建时隐含完成；传统工具一键执行四阶段；主 Agent 开放对话并自主选 MCP 工具，禁止指令类型枚举、关键词路由或固定工具序列替代模型决策。
- 原型 `web/src/prototype/Journey.tsx` / `MasterWorkbench.tsx` 仅作交互参考；固定数组、定时状态和工具播放脚本不得进入正式链路。正式失败不回退演示成功。补齐错误、权限、取消与恢复状态。
- 复用现有 Go 领域服务、Pi / llm、插件、工作流、租约、预算和证据校验。新业务持久化及真实集成验收以 PostgreSQL 为准；不新建 SQLite 功能。旧 API、ID、固定版本和历史数据保持可读。
- 端到端交付 Schema、领域实现、认证 API / MCP（涉及时）、正式 UI、PG 持久化与重启验收、文档。先按 AGENTS.md 确认公开测试边界，再逐项 TDD；运行相关测试、完整乱序竞态、前端测试 / 构建、make lint、make check-contracts；PG 变更跑 make test-postgres，文件系统 / 生命周期变更跑 make test-stress。真实模型/执行器验收不得仅用 mock 代替。
- 不触碰他人 WIP，不通过排除失败包宣称全量通过。提交与关闭按 AGENTS.md 的已授权 Issue 交付流程；push 必须等待用户明确要求。仓库不得出现秘密、个人信息、.env 或私钥。
- 当前任务是待开发规格，不表示已实现；工具名、路由与迁移号实施时与现有注册表核对。主要设计：docs/design/project-agent-architecture.md；接手步骤：docs/design/deepseek-handoff.md。Issue 正文本身包含实现所需的产品与验收约束，不依赖本地尚未推送的文档才可理解。
