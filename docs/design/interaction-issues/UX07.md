## What to build

**类型：AFK。用户故事：** 我可以随时暂停或停止整个审计，也可以只控制一个子任务；重启后状态准确，历史工作仍可查看。

把准备阶段的分析运行、主 Agent 模型请求/工具、路径探索和子任务纳入项目级控制作用域。区分请求与执行器确认，接入现有工作流、Agent 检查点、数据库租约/栅栏，不用前端布尔值立即制造“已停止”。

## Acceptance criteria

- [ ] 项目/会话控制 API 和主 Agent 对应 tools 复用同一应用服务，鉴权、幂等、CAS和操作作用域明确；全局控制包含分析运行、探索、主请求和所属子任务，不影响其他项目。
- [ ] 暂停先阻断新调度/模型请求，再让活动执行到可保存边界，显示 PAUSING→PAUSED；停止显示 STOPPING/CANCELLING 到执行器确认或栅栏回收后才终态。
- [ ] 记录各任务暂停原因/控制批次，继续全部只恢复被该批全局暂停的任务；人工单独暂停保持暂停；暂停期间允许追加消息但不越过边界应用。
- [ ] 停止后旧 generation/lease/tool result/message 不可写入；新一轮指挥有新身份/血缘，不自动复活已停止任务或重跑已完成插件产物。
- [ ] 真实 PG 双 worker/断连/杀进程/恢复重放时，同一任务仅一个有效所有者，连续事件可恢复，预算/指令状态一致，无未回收进程或活动删除绕过。
- [ ] 项目总览与工作台一致展示主子任务/四阶段状态；网络超时显示请求结果未知并可查询，不把失败当成功、停止当完成。
- [ ] 真实 Pi/llm 控制边界、工作流等待/取消、并发控制/迟到结果、项目删除冲突、重启与浏览器操作验收通过；运行 make test-stress。

## 实现切入点

复用 workflow Pause/Cancel/Recover、agent checkpoint/generation、PG clock leases、项目 lifecycle 删除栅栏；新增项目级协调记录，而非另写与已有机制竞争的定时调度器。

## 实施与交付约束

- 按 2026-10-21 已确认原型：一个新项目对应一份源码的一次审计；快照在创建时隐含完成；传统工具一键执行四阶段；主 Agent 开放对话并自主选 MCP 工具，禁止指令类型枚举、关键词路由或固定工具序列替代模型决策。
- 原型 `web/src/prototype/Journey.tsx` / `MasterWorkbench.tsx` 仅作交互参考；固定数组、定时状态和工具播放脚本不得进入正式链路。正式失败不回退演示成功。补齐错误、权限、取消与恢复状态。
- 复用现有 Go 领域服务、Pi / llm、插件、工作流、租约、预算和证据校验。新业务持久化及真实集成验收以 PostgreSQL 为准；不新建 SQLite 功能。旧 API、ID、固定版本和历史数据保持可读。
- 端到端交付 Schema、领域实现、认证 API / MCP（涉及时）、正式 UI、PG 持久化与重启验收、文档。先按 AGENTS.md 确认公开测试边界，再逐项 TDD；运行相关测试、完整乱序竞态、前端测试 / 构建、make lint、make check-contracts；PG 变更跑 make test-postgres，文件系统 / 生命周期变更跑 make test-stress。真实模型/执行器验收不得仅用 mock 代替。
- 不触碰他人 WIP，不通过排除失败包宣称全量通过。提交与关闭按 AGENTS.md 的已授权 Issue 交付流程；push 必须等待用户明确要求。仓库不得出现秘密、个人信息、.env 或私钥。
