**类型：AFK。用户故事：** 报告说明审计了什么、哪些仍未知，以及主 Agent 与子任务如何产生这些证据，后续发现不改变旧报告。

## What to build

沿已有builtin.reporter、Markdown/JSON/SARIF、认证预览/下载扩展固定输入：coverage_contract、ledger_revision、路径集合、发现账本、可用的会话/主子run/消息影响与实际runtime pin。只消费公开记录和可核查来源，不导出隐藏推理/provider原始transcript。

## Acceptance criteria

- [ ] 相同固定输入两次逐字节一致；包含覆盖数字、入口分类、frontier/blocker和完成性，三格式及Schema语义一致。
- [ ] 主 Agent 新增路径、后续子任务与新消息不改写旧报告；报告列出固定时点/版本及其后的结果是否未纳入，不能静默使用latest。
- [ ] 包含可用的runtime/worker/protocol/model/config/tool pin、checkpoint/resume血缘、用量来源及主会话/父子任务/发现来源引用；缺字段显示未记录，不用当前设置补历史。
- [ ] 候选/已确认、优先级/严重性、阶段/run结束/覆盖达标继续独立；被主 Agent 关注或静态告警不能作为漏洞确认。
- [ ] 原始秘密/隐藏推理不入报告；复用认证下载、大小和SHA-256检查、历史目录与失败/取消不发布半成品语义。
- [ ] PostgreSQL、旧报告兼容、权限/Scope/固定边界/重启和正式页面真实预览下载验收通过；主 Agent尚未上线时不阻塞已有边界报告。

## 本轮开发共同约束（2026-10-21）

本单已按当前前端原型与主 Agent 设计修订。新项目是一份源码的一次审计，创建时隐含保存输入；默认一键四阶段传统分析。主 Agent 使用自由对话，由模型自主选择 MCP 工具，禁止用户指令类型枚举、关键词路由及固定工具序列替代模型决策。实际进程、scope、权限、预算、幂等、租约和证据校验仍由宿主负责。

复用已交付 Go / Pi / llm、插件、工作流、PG、认证和证据能力，保留旧 API / ID / 固定版本与历史项目。新业务仅维护 PostgreSQL，Memory 可作测试双；SQLite 仅历史读取或迁移源，不新增 SQLite 功能/CI门槛。原型是模拟数据，不能进入正式执行或作为真实验收证据。

交付必要的契约、真实后端、认证 API / MCP、正式 UI、PG持久化、文档与验收。遵守 AGENTS.md：确认公开边界后逐项 TDD，相关测试、完整乱序竞态、make lint、make check-contracts、前端测试/构建；PG改动跑 make test-postgres，文件系统/生命周期跑 make test-stress。不得改动他人WIP或排除失败包后宣称全量通过。验收后的 commit/关闭按既有授权流程，push 仍须用户明确要求。秘密、个人信息、.env和私钥不得入库。
