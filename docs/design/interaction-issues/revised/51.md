## What to build

**类型：AFK**

**用户故事：** 模型可以直接问"这个快照有哪些入口点、哪些 sink、这个节点为什么存在"，并用一份很小的仓库地图定位，而不是靠计数和猜测开始探索。

新增 `list_entry_points`、`list_sinks`、`get_asg_node`（均带证据与边界）与 `repo_map`（顶层模块分布、入口点分布、sink 分布、未解析率 Top 5，控制在 ≤500 token）。全部只读、快照域内、有界返回。

实现基线：`d801502`；方案：`docs/design/agent-loop-remediation-draft.md` §2 K03 / K04。

## Acceptance criteria

- [ ] `list_entry_points` 与 `list_sinks` 支持类型过滤与 limit 上限，返回主体、位置与证据状态。
- [ ] `get_asg_node` 返回节点、证据引用与 `detail`（含"未评估有效性"等限定），未知节点返回明确错误。
- [ ] `repo_map` 输出 ≤500 token，含模块分布、入口点按边界、sink 按类型、未解析率 Top 5 与覆盖说明。
- [ ] 全部工具只读、快照域内、拒绝未知参数；结果可被答案引用并在报告中还原。
- [ ] 黄金集上每条路径的探索轮数平均减少 ≥1 轮。
