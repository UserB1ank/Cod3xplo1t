## What to build

**类型：AFK**

**用户故事：** 审计中最常见的两个问题——"谁调用了这个模式"和"哪些调用点解析不了"——可以直接问，而不必靠符号名猜测。

新增 `search_code`（字面 / 正则、glob 过滤、只读冻结树、有界结果）与 `list_unresolved_calls`（对齐既有 MCP 面并增加按原因过滤）。两者都纳入 Agent 工具白名单、预算与事件记录，返回结构完整、裁剪原因写在结果内。

实现基线：`d801502`；方案：`docs/design/agent-loop-remediation-draft.md` §2 K01 / K02。

## Acceptance criteria

- [ ] `search_code` 支持字面与正则、glob 过滤、matches ≤ 20、单行文本 ≤ 200 字符、扫描文件数与超时上限，只读冻结快照树。
- [ ] `list_unresolved_calls` 支持 `caller_symbol_id` 与 `reason`（dynamic / ambiguous / external / unsupported）过滤，limit 有上限。
- [ ] 两工具拒绝未知参数与越界预算，裁剪与截断信息写在结果内，不产生半截 JSON。
- [ ] 工具结果带证据 id，可被答案引用并在报告中还原为文件与行号。
- [ ] 用 #47 的 blocker 数据证明：对应 blocker 类型的占比在黄金集上可测量地下降。

## 本轮开发共同约束（2026-10-21）

本单已按当前前端原型与主 Agent 设计修订。新项目是一份源码的一次审计，创建时隐含保存输入；默认一键四阶段传统分析。主 Agent 使用自由对话，由模型自主选择 MCP 工具，禁止用户指令类型枚举、关键词路由及固定工具序列替代模型决策。实际进程、scope、权限、预算、幂等、租约和证据校验仍由宿主负责。

复用已交付 Go / Pi / llm、插件、工作流、PG、认证和证据能力，保留旧 API / ID / 固定版本与历史项目。新业务仅维护 PostgreSQL，Memory 可作测试双；SQLite 仅历史读取或迁移源，不新增 SQLite 功能/CI门槛。原型是模拟数据，不能进入正式执行或作为真实验收证据。

交付必要的契约、真实后端、认证 API / MCP、正式 UI、PG持久化、文档与验收。遵守 AGENTS.md：确认公开边界后逐项 TDD，相关测试、完整乱序竞态、make lint、make check-contracts、前端测试/构建；PG改动跑 make test-postgres，文件系统/生命周期跑 make test-stress。不得改动他人WIP或排除失败包后宣称全量通过。验收后的 commit/关闭按既有授权流程，push 仍须用户明确要求。秘密、个人信息、.env和私钥不得入库。
