## What to build

**类型：AFK。用户故事：** 创建项目后点击一次“开始图谱化分析”，自动依次完成代码图谱、安全语义/攻击面、候选路径和筛选评分；始终知道当前是哪一阶段。

使用固定版本默认工作流/计划复用内置 parse → semantic → paths → enhancement 和必要的发布节点。新增项目级 AnalysisRun 聚合，不把一次阶段运行冒充路径审查子任务。默认传统工具独立工作，Agent 语义增强为可选能力；新模型能力缺失不阻断默认分析。

## Acceptance criteria

- [ ] ready 项目从正式总览一键启动，自动推进四阶段，无须先进入工作流/插件页配置；持久化 analysis_run_id、阶段顺序/状态、固定计划、invocation、输出/知识版本和覆盖局限。
- [ ] 每阶段输出来自真实插件/算法，筛选增强使用 #29；成功只在产物和状态发布后显示。完成事件可恢复，真实进度没有分母时使用状态而非虚构百分比。
- [ ] 并发/重复启动幂等或明确冲突；失败停止依赖阶段，预算/截断/未知标为部分覆盖，不能直接写成全部完成；历史运行与当前运行不混淆。
- [ ] 默认无 LLM 仍可走完四阶段。显式选择 Agent 辅助时检查实际能力/配置，记录调用与假设来源，失败不伪装为规则事实。
- [ ] 重启/双实例接管沿现有 workflow 租约与栅栏，已完成阶段复用固定产物，不重复发布；旧 generation 输出拒绝。项目删除与活动运行互斥。
- [ ] 用户可从阶段详情查看输入、工具版本、覆盖、跳过/失败原因；完成后进入局部图谱或审查路径，不自动启动 LLM 子任务。
- [ ] 真实 PG + 容器/页面验收完整运行、模型未配置、阶段失败、预算截断、重复启动、重启复用与跨项目拒绝。

## 实施与交付约束

- 按 2026-10-21 已确认原型：一个新项目对应一份源码的一次审计；快照在创建时隐含完成；传统工具一键执行四阶段；主 Agent 开放对话并自主选 MCP 工具，禁止指令类型枚举、关键词路由或固定工具序列替代模型决策。
- 原型 `web/src/prototype/Journey.tsx` / `MasterWorkbench.tsx` 仅作交互参考；固定数组、定时状态和工具播放脚本不得进入正式链路。正式失败不回退演示成功。补齐错误、权限、取消与恢复状态。
- 复用现有 Go 领域服务、Pi / llm、插件、工作流、租约、预算和证据校验。新业务持久化及真实集成验收以 PostgreSQL 为准；不新建 SQLite 功能。旧 API、ID、固定版本和历史数据保持可读。
- 端到端交付 Schema、领域实现、认证 API / MCP（涉及时）、正式 UI、PG 持久化与重启验收、文档。先按 AGENTS.md 确认公开测试边界，再逐项 TDD；运行相关测试、完整乱序竞态、前端测试 / 构建、make lint、make check-contracts；PG 变更跑 make test-postgres，文件系统 / 生命周期变更跑 make test-stress。真实模型/执行器验收不得仅用 mock 代替。
- 不触碰他人 WIP，不通过排除失败包宣称全量通过。提交与关闭按 AGENTS.md 的已授权 Issue 交付流程；push 必须等待用户明确要求。仓库不得出现秘密、个人信息、.env 或私钥。
- 当前任务是待开发规格，不表示已实现；工具名、路由与迁移号实施时与现有注册表核对。主要设计：docs/design/project-agent-architecture.md；接手步骤：docs/design/deepseek-handoff.md。Issue 正文本身包含实现所需的产品与验收约束，不依赖本地尚未推送的文档才可理解。
