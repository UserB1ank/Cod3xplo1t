## What to build

**类型：AFK。用户故事：** 图谱化完成后，从程序入口查看小范围模块调用，核对源码，再选择值得交给 Agent 的路径。

将原型代码图谱与路径清单接到固定知识视图/版本、真实候选路径和增强 lineage。沿现有 PostgreSQL 图查询浏览，不新增图数据库服务器/控制台。模型发现路径后也使用同一清单，保持路径身份和证据等级。

## Acceptance criteria

- [ ] 项目入口目录支持搜索/分页；选入口默认 1–2 跳模块/符号调用关系，按需有界展开与深度限制，明确截断与未解析边。
- [ ] 点击节点/边能读取固定视图对应源码、静态证据和来源；无入口或图不可用/失效有真实空/错误状态，不能展示示例图。
- [ ] 路径显示 entry/sink、调用或数据证据等级、源文件位置、优先级、评分/过滤原因、工具/Agent/人工来源和覆盖局限。
- [ ] 选择若干路径通过正式应用服务生成有稳定 ID、可独立控制的子任务；记录现有 audit/task/path/run 的映射，重复选择幂等，不按标题合并。
- [ ] 旧视图失效、跨快照引用、路径不存在和权限不足明确返回错误；优先级不是漏洞严重度、调用可达不是污点流、过滤不是安全证明。
- [ ] 主流程可查看初始工具路径；UX05 上线后同页分页/计数/来源过滤接收 Agent 新路径，不把路径数组固定为五条。
- [ ] UI 键盘选择、窄屏、真实 PG 重启、认证隔离和浏览器从入口→源码→路径→任务验收通过。

## 实现切入点

`internal/knowledge`、`internal/graph`、`internal/path`、知识版本目录、`web/src/Knowledge.tsx`、任务应用服务。主流程不依赖任意 Cypher/SQL。
