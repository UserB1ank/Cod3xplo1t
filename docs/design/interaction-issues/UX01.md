## What to build

**类型：AFK。用户故事：** 创建项目时导入一份源码，完成后直接进入项目总览；可以编辑名称/说明、查看输入与产出入口、删除当前项目，不需要手动固定快照或更新代码。

在现有项目/来源/导入/lifecycle 服务上增加新项目的显式审计输入绑定与 importing / ready / failed 生命周期。复用归档、浏览器目录和 Git 输入；默认界面不暴露额外代码源/快照创建步骤。新流程只保存输入，不提前把四阶段分析声明完成。旧多来源/多快照项目原样保留，不能选 latest 冒充唯一输入。

## Acceptance criteria

- [ ] 通过正式创建表单导入归档、目录或 Git 时，后台自动保存输入和 snapshot 引用，ready 后立即显示“开始图谱化分析”；无需模型配置，不自动启动 Agent 或昂贵分析。旧导入 API 行为兼容。
- [ ] 幂等创建、重复/并发请求、取消、导入失败和重启均不会留下重复 ready 项目或丢失输入；失败呈现真实原因并可清理/重试。
- [ ] 名称/说明编辑使用服务端版本校验；源码绑定不可通过普通编辑换成另一份代码，界面不提供“更新代码”。另一份源码另建项目。
- [ ] 总览和目录可读取真实输入、任务/发现/报告入口；缺产出显示零或未生成，不填原型数字。聚合与搜索的完整实现另由 #22 承担。
- [ ] 项目删除为正式 writer 能力，先校验活动分析、会话/子任务、插件、验证及引用；冲突明确拒绝或要求先停止。删除意图、数据清理和 filesystem/store 栅栏可恢复，不能只删除前端列表行。
- [ ] 删除不破坏其他项目共享内容，不让迟到写入复活项目；示例初始化标记与项目删除独立。数据重建后删除状态一致。
- [ ] 旧项目 ID、来源、快照、任务和证据完整保留；旧多输入项目有兼容提示和明确选择上下文，不强制无损性未经验证的自动拆分。
- [ ] 真实 PG/认证 API 和浏览器验收包括三类输入、编辑 CAS、跨项目拒绝、活动删除冲突、导入/删除中断恢复、重启和旧项目升级。

## 实现切入点

`internal/api/server.go` 的项目/来源路由、`internal/lifecycle`、已有上传客户端/表单、`internal/storage`。目前有项目 PATCH 与快照 DELETE，不能假设已有完整项目 DELETE。如需新 DTO/API，明确版本并登记公共契约。

## Blocked by

无新增阻塞；复用已完成的源码导入、PG、认证和基础图谱能力。

## 实施与交付约束

- 按 2026-10-21 已确认原型：一个新项目对应一份源码的一次审计；快照在创建时隐含完成；传统工具一键执行四阶段；主 Agent 开放对话并自主选 MCP 工具，禁止指令类型枚举、关键词路由或固定工具序列替代模型决策。
- 原型 `web/src/prototype/Journey.tsx` / `MasterWorkbench.tsx` 仅作交互参考；固定数组、定时状态和工具播放脚本不得进入正式链路。正式失败不回退演示成功。补齐错误、权限、取消与恢复状态。
- 复用现有 Go 领域服务、Pi / llm、插件、工作流、租约、预算和证据校验。新业务持久化及真实集成验收以 PostgreSQL 为准；不新建 SQLite 功能。旧 API、ID、固定版本和历史数据保持可读。
- 端到端交付 Schema、领域实现、认证 API / MCP（涉及时）、正式 UI、PG 持久化与重启验收、文档。先按 AGENTS.md 确认公开测试边界，再逐项 TDD；运行相关测试、完整乱序竞态、前端测试 / 构建、make lint、make check-contracts；PG 变更跑 make test-postgres，文件系统 / 生命周期变更跑 make test-stress。真实模型/执行器验收不得仅用 mock 代替。
- 不触碰他人 WIP，不通过排除失败包宣称全量通过。提交与关闭按 AGENTS.md 的已授权 Issue 交付流程；push 必须等待用户明确要求。仓库不得出现秘密、个人信息、.env 或私钥。
- 当前任务是待开发规格，不表示已实现；工具名、路由与迁移号实施时与现有注册表核对。主要设计：docs/design/project-agent-architecture.md；接手步骤：docs/design/deepseek-handoff.md。Issue 正文本身包含实现所需的产品与验收约束，不依赖本地尚未推送的文档才可理解。
