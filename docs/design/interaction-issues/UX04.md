## What to build

**类型：AFK。用户故事：** 在独立工作台向项目主 Agent 提问，它根据对话自主回答或查询真实图谱/源码，不需要选择指令类型。

建立持久项目会话、消息、有序事件和主 Agent run，复用现有模型设置及 Pi/llm 工具桥接。通过真实 MCP SDK 的目录/调用接入后端领域工具，并沿 Go ToolDescriptor/Registry 共用参数校验。此切片先给主 Agent 只读查询；写能力在 UX05/UX06 单独交付。

## Acceptance criteria

- [ ] 主 Agent 工作台为默认会话，文本输入不含 intent/action_type 枚举；前后端均无关键词路由到固定工具序列。只需问答时允许零工具/零写入，也允许先澄清。
- [ ] 主 Agent 拥有独立 session/run 身份和公开自然语言答复通道；不能伪造 AuditPath 以复用旧路径 TaskBuilder，不能把聊天文字当路径审查结构化结论。路径子 Agent 原有 schema 2/义务校验保持。
- [ ] 会话与消息 PG 落库，发送幂等、有界历史/摘要、事件游标/重连、runtime/model/config/tool pin、上下文引用、用量及取消状态真实可读；不保存隐藏推理或秘密。
- [ ] 真实 MCP tools/list 与 tools/call（或 SDK 等价调用）验收成功，领域逻辑不在 MCP adapter/TypeScript 重写；旧 stdio 九个只读工具保持兼容，不默认为其增加项目写权限。
- [ ] 项目、snapshot、身份和允许工具由宿主绑定，不接受模型通过参数更换项目。每次执行同时校验权限、预算/限额和真实能力；MCP 错误配对回灌而非伪造成功。
- [ ] 工具目录与现有 Go Registry 同源；主 Agent / 路径 Agent 按角色暴露能力。复合参数需求采用有界 Schema 支持，不退回 JSON 字符串 wrapper 或任意查询语言。
- [ ] 先复用现有图谱/源码工具形成闭环；#50/#51 后续按同一目录扩展，不把它们设成首个开放会话的硬阻塞。模型不可用展示原因，不回退 ScriptedRuntime。
- [ ] 使用合成 provider/MCP 测试验证两种不同提示产生不同工具组合及纯回答不写入；再以已授权真实模型验收自然问答和图查询。认证/PG 重启/消息重放/跨项目/预算与取消用例通过。

## 实施与交付约束

- 按 2026-10-21 已确认原型：一个新项目对应一份源码的一次审计；快照在创建时隐含完成；传统工具一键执行四阶段；主 Agent 开放对话并自主选 MCP 工具，禁止指令类型枚举、关键词路由或固定工具序列替代模型决策。
- 原型 `web/src/prototype/Journey.tsx` / `MasterWorkbench.tsx` 仅作交互参考；固定数组、定时状态和工具播放脚本不得进入正式链路。正式失败不回退演示成功。补齐错误、权限、取消与恢复状态。
