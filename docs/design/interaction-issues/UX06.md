## What to build

**类型：AFK。用户故事：** 主 Agent 可以按我的审计目标安排路径审查，并修正某个子 Agent 的方向；我也能直接进入子任务对话或控制运行。

新增项目作用域的任务创建/调度/消息/单任务控制 MCP 能力，全部调用既有任务、scheduler、agent Runner 与仓储。主 Agent 发起协调请求，Go 宿主决定租约、并发、预算、进程和有效动作。与 UX05 无强依赖，可先调度工具初始路径。

## Acceptance criteria

- [ ] 模型通过 tools 选择目标路径、创建/调度真实子任务；独立 task/audit/path/child_run ID 与 parent session/run 关联可查，不将主 Agent 进程当执行器监督器。
- [ ] 工作台左侧任务面板展示真实状态/受阻原因，中央可切换主会话或子任务，右侧上下文可引用到主对话；无需为消息选择行为类别。
- [ ] 指令/消息持久化包含发送方、目标、序号、generation/版本和回执；pending→received→applied 或 rejected/not_applied 有明确条件，下一受控执行边界应用。
- [ ] 运行中能接收主 Agent 或人工消息；暂停可排队，终态/旧 generation 明确未应用；取消/重试/检查点续跑后不会把旧消息静默施加到新 attempt。现有证据和结论保留，修正另记事件。
- [ ] 人工和主 Agent 同时调整同一子任务按服务端顺序/CAS处理，不能前端点发送就宣称已应用；子 Agent 显示采纳方式或拒绝理由的公开摘要。
- [ ] reader/writer、同项目归属、任务存活性、并发、总预算与单任务预算均由宿主校验；主 Agent 无权自行追加额度、审批动态执行或扩大工具权限。
- [ ] 先复用 Pi/llm 已有 runtime pins、检查点和批次协议；不新增另一个模型 SDK/直接数据库控制器。开启自动调度时不会启动人工单独暂停的任务。
- [ ] 实际 MCP→领域服务→子 Agent 工具与回答闭环，PG 双实例投递/重启/幂等、同目标竞争/权限/迟到消息与真实模型纠正行为页面验收通过。

## 实现切入点

`internal/schedule`、`internal/path`、`internal/agent` 控制与恢复边界、PG lease_epoch、任务/运行事件 API；扩展运行中消息投递，不把消息伪装为重新创建任务。

## 实施与交付约束

- 按 2026-10-21 已确认原型：一个新项目对应一份源码的一次审计；快照在创建时隐含完成；传统工具一键执行四阶段；主 Agent 开放对话并自主选 MCP 工具，禁止指令类型枚举、关键词路由或固定工具序列替代模型决策。
- 原型 `web/src/prototype/Journey.tsx` / `MasterWorkbench.tsx` 仅作交互参考；固定数组、定时状态和工具播放脚本不得进入正式链路。正式失败不回退演示成功。补齐错误、权限、取消与恢复状态。
