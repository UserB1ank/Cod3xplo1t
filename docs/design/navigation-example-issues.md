## N01 — 功能导航始终显示，模型设置和数据存储统一收进底部配置

### What to build

**类型：AFK。用户故事：** 用户登录后即可看到完整功能列表，不再因为选择项目突然出现一批菜单；应用级设置始终从侧栏底部的“配置”进入。

将项目概览、任务、代码源、知识图谱、漏洞库、报告、产物、插件、工作流和项目设置保留在固定顺序的侧栏中。没有项目上下文时提供明确的选择 / 创建项目状态，选择项目后进入刚才请求的功能。底部新增统一配置页面，包含模型设置与数据存储；项目设置继续归属项目。复用真实 API、权限与持久化，不重复建设设置后端。

### Acceptance criteria

- [ ] 登录后未选项目、已选项目、切换项目时，功能菜单的数量和顺序稳定；未选项目时不会发出带空项目 ID 的请求，也不会突然选择错误项目。
- [ ] 未选项目点击功能后显示选择 / 创建项目引导，选好项目进入目标功能；浏览器刷新、前进 / 后退与深链接行为一致。
- [ ] 侧栏底部只有统一“配置”入口，模型设置和数据存储作为其子页；移除旧顶栏模型快捷入口及旧侧栏独立入口。
- [ ] 原模型 / 存储深链接兼容跳转到配置子页；模型保存、连接测试、版本 CAS 与存储状态继续读取真实认证 API。
- [ ] 管理员权限继续由后端校验；非管理员或未启用能力显示明确说明，不能通过路由改写获得权限。
- [ ] 短屏幕与窄窗口侧栏可滚动，底部配置与退出可达，键盘焦点、当前页标识和页面标题正确。
- [ ] 前端路由 / 渲染行为测试及构建通过，浏览器验收未选项目、切换项目、配置两子页、旧链接与移动布局；API 权限相关回归通过。

### Blocked by

None - can start immediately. 与启动示例项目独立，不借助示例数据掩盖无项目状态。

## N02 — 服务启动创建真实示例项目，登录页移除示例入口

### What to build

**类型：AFK。用户故事：** 初次启动后，用户正常登录即可打开一个可操作的示例项目，查看真实源码快照和图谱；登录界面专注认证，不出现“示例 / 原型”入口。

随程序嵌入一份小型、无真实秘密、无需网络与外部依赖的合成源码。Web 服务启动时通过正式项目、快照与图谱链路建立示例数据，持久化初始化标记并区分示例项目。默认只初始化一次；重启不重复建立，删除后不自动复活，不覆盖用户修改。初始化不自动创建 LLM 任务、不调用模型、不设置账号或凭据，也不写入虚构漏洞结论。

### Acceptance criteria

- [ ] 空环境首次启动创建一个明确标为“示例”的项目和真实冻结源码快照；正常登录后出现在正式项目列表，源码 / 图谱可读，可按正常权限手动创建任务。
- [ ] 示例源码通过普通解析与图谱构建获得真实节点 / 边与来源，不将 `/prototype/` 或前端演示数组灌入正式接口。
- [ ] SQLite / PostgreSQL 均保存初始化标记和项目 / 快照引用；重复启动、双实例并发启动、初始化中断恢复不重复创建，也不覆盖已有项目。
- [ ] 用户删除示例后下次启动不自动复活；初始化标记独立于项目存在性。已有正常项目的升级环境也至多补建一个示例。
- [ ] 初始化只使用程序内合成源码，不依赖宿主路径、Git 网络、Docker socket、模型配置或安装器；不自动运行工作流 / LLM，不使用真实用户名或凭据。
- [ ] 初始化失败明确记录和呈现真实状态，可重试，不生成宣称就绪的半成品；已有项目与登录仍可用，失败不重置用户数据。
- [ ] 登录 / 初始化账号界面移除示例、原型和绕过登录入口；未认证用户仍无法访问示例的正式 API。现有独立原型路由是否保留不影响正式登录。
- [ ] 按确认的启动公开边界完成逐项 TDD，覆盖真实快照、重启 / 并发幂等、删除后不复活、失败恢复和认证；完整竞态、`make test-stress`、真实 PG、`make lint`、契约、前端测试 / 构建和独立容器浏览器验收通过。

### Blocked by

None - can start immediately. 使用既有正式代码源 / 快照和图谱能力，不等待浏览器上传功能。
