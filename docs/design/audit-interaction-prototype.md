# 审计流程交互原型

此文档记录 2026-10-21 讨论后的产品交互方案。原型入口 `/prototype/`，使用内存示例，不调用业务 API；刷新重置，不表示后端能力已经实现。

## 项目语义

一个项目对应一份源码的一次审计，下属有多个路径审查任务。创建项目时导入代码、自动保存内部审计输入；不向用户暴露单独的快照操作，不提供更新代码入口。项目名称与说明可以编辑，可查看产出、任务与报告。另一份源码创建另一项目。

## 用户流程

1. 创建项目，选择源码归档。原型也提供“使用示例源码体验流程”，不上传文件。
2. 项目总览显示源码就绪，点击“开始图谱化分析”。
3. 自动串行推进代码图谱构建、安全语义与攻击面识别、候选路径生成、路径筛选与评分；展示当前阶段与完成状态。默认传统工具，可在开始前选择 Agent 辅助增强。
4. 完成后可浏览入口局部调用图，选择一至三层展开深度，点击节点查看示例源码关联。
5. 路径清单展示入口、敏感操作、优先级、筛选原因和局限；人工增选或排除路径，进入 Agent 审查。
6. 每条选中路径生成独立待审查任务。在独立工作台启动，查看动作与证据摘要；暂停保留上下文，继续恢复，停止结束本次运行。
7. 人工方向记录待接收、已应用、未应用。运行到下一执行边界时应用；暂停期间保持待接收；停止后未接收的方向标为未应用。
8. 已完成审查在发现页显示候选及记录。报告页生成、预览与下载示例 Markdown 报告。

## 页面结构

- 所有项目：创建与进入项目。
- 项目总览：项目管理、四阶段进展、路径与任务数量、候选与已确认数量、报告数量、产出入口。
- 代码图谱：入口搜索、局部调用关系、展开深度、源码关联与覆盖局限。
- 审查路径：选择范围、路径摘要、筛选与过滤原因。
- Agent 工作台：任务面板、执行记录、启动/暂停/继续/停止、人工方向、任务上下文。
- 发现与证据：候选、证据、局限与原任务链接。
- 审计报告：目录、预览和下载。

## 原型边界与正式实现待办

四阶段定时推进与 Agent 事件均为模拟；文件仅记录名称；示例入口、调用图、源码和路径不来自上传文件。Agent 辅助开关仅展示编排选择，未调用模型。图谱提供产品内浏览，不连接外部图数据库控制台。

正式实现需接入真实阶段状态、工具覆盖与失败详情、事件流、执行取消确认、方向回执和报告固定输入。真实停止必须展示停止请求到执行器确认的过程；原型中的本地定时器可直接停止。人工方向不能自动成为已验证事实；静态调用可达不能冒充数据流；优先级不是漏洞严重度；候选不是已确认漏洞。

原有通用原型组件和接口目录保留在源码中，本轮只切换原型入口，不修改正式 UI 或 API。

## 主 Agent 指挥工作台

工作台以主 Agent 为默认入口。左侧切换主 Agent、图谱探索与路径审查子任务；中央展示会话、工具动作、计划及执行记录；右侧显示项目范围、本轮审计方向、执行边界、选中子任务和指令回执。

- 主 Agent 可演示三步图谱探索，新增有来源说明的候选路径；项目总览、路径清单和图谱入口同步消费新增路径，重复探索不重复添加。
- 对话入口完全开放，不设置指令类型，不使用前端枚举或关键词路由。正式版本由模型结合会话与项目上下文自主决定回答、查询、探索、调度、修正或其他工具组合；后端 MCP 暴露有明确输入输出的能力。普通已授权动作无需逐轮确认计划。
- 当前原型未接入模型：自由对话只记录输入，不声称已理解或执行；单独的“播放工具调用示例”运行预设轨迹，展示工具对项目的影响，与用户任意输入无关。
- 选中子任务可“引用到主 Agent 对话”，仅附带任务上下文，不指定操作类型。用户仍可直接与子 Agent 对话。
- 项目审计方向保存在当前项目内存状态中，向现有未结束子任务下发，并随主 Agent 后续调度继续传递。子任务在下一执行边界回执已应用；停止前未接收的方向标为未应用。
- 执行策略可调整同时审查上限（1–3）、每轮新增路径上限（1–2），以及新路径是否自动创建审查子任务。默认新路径等待人工选择。
- 调度队列按并发上限推进；人工单独暂停的子任务不会自动恢复。暂停全部冻结探索、调度和运行中的子任务；继续全部只恢复由全局暂停的任务；停止全部结束本轮及其未完成子任务，保留历史记录。
- 用户能直接进入子任务，查看记录、发送方向、单独启动、暂停或停止。主 Agent 的方向同样保留回执与原始证据。

本次仍是本地原型，无真实模型、图谱查询、子进程执行或数据库写入。探索只使用两个预设路径样例；其数量与去重行为用于验证交互，不表示真实漏洞发现能力。


## 开放对话与 MCP 执行原则

用户对话 → 模型结合会话、项目状态与工具描述决定回应或调用 → 后端校验并执行 MCP 工具 → 工具结果回灌模型 → 继续执行或回应。工具调用次数及组合由任务需要决定，不要求每条对话都产生写入。

工具具有明确契约，不等于用户必须选择指令类型。可提供图谱查询、源码读取、路径提交、任务创建 / 调度 / 消息 / 控制、证据与报告查询等工具；这些是能力示例，正式实现应对齐现有 API 与作用域。模型不能直接改数据库；宿主负责项目范围、权限、预算、并发、幂等及审计记录。只有需要额外授权的工具请求人工决定。

UI 展示会话、可核查的工具行动与结果、子任务状态，允许查看工具调用详情。暂停和停止保留为直接控制入口。无需暴露意图分类器或要求用户选择“新增路径”等业务指令类型。
