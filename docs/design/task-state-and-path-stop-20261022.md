# 任务操作状态与项目批量停止修复

日期：2026-10-22。

## 任务状态与按钮

任务的 `paused` 表示是否允许调度新路径，不能据此判断任务是否正在运行。原任务表只用它切换暂停 / 播放图标，导致路径进度已经结束时仍显示暂停。

正式任务表与任务详情共用 `taskSchedulingControl`：

- 原生路径全部形成假设或结束，显示不可点击的完成标记；全部取消显示已停止，混合完成与取消显示已结束。
- 活动任务继续提供暂停 / 恢复调度；工作流任务由工作流面板控制。
- 归档优先显示已归档。已完成任务可以直接归档，客户端先通过现有 CAS API 关闭调度，再使用响应的新 ETag 归档。服务端仍验证没有活动路径 / Agent / 验证运行。

这里的完成表示路径审查阶段结束，不把候选假设变成已确认漏洞。

## 停止当前项目的路径

正式项目总览、任务管理、审查路径、Agent 工作台、任务详情及删除对话框提供“停止所有路径”。停止与删除分开，停止不会删除证据或报告，也不会自动触发删除。

认证接口：

- `POST /api/v1/projects/{projectID}/stop-paths`，writer，空 JSON 请求。
- `GET /api/v1/projects/{projectID}/stop-paths`，reader，查询当前剩余工作。
- 公共响应契约：`contracts/v1/project-path-stop.schema.json`。

`internal/lifecycle.ProjectPaths` 枚举当前项目的全部任务与路径，先请求取消关联的活动工作流，使用任务 CAS 关闭调度，再通过现有路径状态机取消未结束路径。分页使用稳定的路径 ID 顺序，不因状态变化跳过后续页。并发版本冲突有界重读；部分失败保留真实错误，可重复请求。已完成路径不改变，其他项目不受影响。

本机运行收到取消信号；策略收窄的 Runner 副本共享同一取消登记。远端 worker 通过数据库中的路径租约失效得知取消，旧租约不能续租或提交中间状态。响应不会把运行记录直接改成成功或停止：运行中的 Agent / 验证执行仍要等待所属执行器结束。已经在检查点暂停的 Agent 没有活动执行器，在路径取消后可事务性结束为 CANCELLED，保留检查点、预算和连续事件。

响应区分 `STOPPING`、`STOPPED`、`PARTIAL`，同时列出剩余路径、Agent、验证运行、工作流和逐项错误。浏览器轮询等待执行器收束；网络错误显示结果尚未确认，可重试。同步四阶段 AnalysisRun 的真实工作流终态，避免取消结束后留下陈旧的活动聚合阻止删除。

STOPPED 只表示本接口观察到的路径、所属工作流和运行已经结束。删除仍由原有项目生命周期核对导入、独立插件、验证计划及环境等阻塞条件。

## 范围

这是现有路径队列的批量停止入口，不是 #69 的完整项目级控制批次。它不禁止用户之后明确创建新任务或恢复调度，也不实现“继续全部”的暂停归因；源码导入、独立插件调用与主 Agent 对话仍使用各自控制。未新增 MCP 管理能力或 SQLite 专属迁移。
