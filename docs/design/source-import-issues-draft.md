## 已有能力与本轮目标

正式创建项目页已经支持 `local_folder` 与 `git_repository`。前者当前要求部署者预先登记只读目录，再填写 `/repos/...`；后者已经支持 HTTPS / SSH、凭据引用、分支 / 标签 / 固定提交。本轮复用远程 Git 能力，增加浏览器上传入口。

用户选择“本地代码”后，可选择上传压缩包或选择电脑上的目录；上传完成并固定快照后，继续使用正式图谱、任务和分析流程。页面要区分选择、上传、服务端校验、建立快照、建立图谱及失败状态。上传成功本身不代表分析就绪。

本轮发布 S01–S03。S04 是附加 HITL 切片，批准前不进入实施范围。导航与启动示例的关联方案见 [界面整理 Issues](navigation-example-issues.md)。

## 动态挂载的可行性与取舍

- 浏览器目录选择器提供文件与相对路径，可用于上传；它不授予 Docker 控制权，也不能把浏览器电脑路径直接当作容器路径。[MDN 目录选择器](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/webkitdirectory)
- Docker bind mount 指向 Docker daemon 所在宿主；远程服务器不能据此挂载浏览器电脑目录。Mac Docker Desktop 通过虚拟机共享机制访问 Mac 文件。[Docker bind mounts](https://docs.docker.com/engine/storage/bind-mounts/)
- 标准 `docker container update` 没有增加 bind mount 的选项。因此常规实现应重建带挂载的容器，或由受控宿主连接器创建临时采集容器；不采用给现有应用容器注入挂载的特权技巧。[Docker update](https://docs.docker.com/reference/cli/docker/container/update/)
- 本方案判断：让 Web 应用直接持有 Docker socket 并接受任意宿主路径，风险高。Docker 官方特别提醒 Web 服务控制 daemon 时必须严查参数；可控制 daemon 的进程具有创建高权限容器和暴露宿主文件的能力。[Docker Engine security](https://docs.docker.com/engine/security/)
- 只读挂载只能限制写入，不能阻止已授权目录中的内容被读取。默认采用显式上传；大目录和反复采集场景可以继续使用已有的部署侧只读根目录登记，也可以另行批准 S04。
- 所有分析都读取冻结快照。即便未来支持挂载，本轮也不引入自动监听文件变化；用户主动更新才建立新快照。

## 共同交付约束

- 每项交付完整用户路径，包含必要的公共契约、认证 API、正式 UI、持久化、文档及真实验收。旧 API、已有代码源、快照、任务、凭据引用和登录行为保持兼容。
- 新导入元数据支持 Memory / SQLite / PostgreSQL；源码内容沿用 ArtifactStore 的逻辑引用与当前持久化能力，不把临时绝对路径当成可移植身份。与 #19 共享产物抽象，但不以其完成为前提，也不宣称本轮完成跨宿主产物共享。
- 公共接口按项目授权，拒绝跨项目操作；上传入口需要写权限。接口 DTO 经公共 Schema 校验，展示真实错误，不使用演示成功兜底。
- 不执行目标代码的 build、test、hook 或安装脚本。默认排除明确敏感文件类型，并报告被排除的内容与覆盖局限；不承诺文件名过滤能够识别所有源码中的秘密。
- 上传暂存有大小、文件数、时间和磁盘预算。取消、断连、服务重启、重复 finalize、并发删除不能发布半成品或破坏已引用内容；清理必须服从活动操作与产物引用栅栏。
- 不在仓库、测试样例、日志或公开错误中加入真实凭据、个人信息、宿主用户名或绝对宿主路径。测试使用合成数据与临时目录。
- 按项目要求在确认公开测试边界后逐项 TDD red → green；执行相关测试、完整乱序竞态回归、前端测试 / 构建、`make lint`、契约检查。文件系统和生命周期变更运行 `make test-stress`，PostgreSQL 变更运行真实隔离集成测试。
- 完成并验收后遵守 AGENTS.md 的逐 Issue 提交与关闭流程；push 仍等待明确指令。

## S01 — SQLite / PostgreSQL Docker 部署统一 Web 默认入口 18085

### What to build

**类型：AFK。用户故事：** 无论选择哪一种正式 Docker 部署，用户都从 `http://127.0.0.1:18085` 打开应用。

统一 `compose.yaml`、`compose.postgres.yaml` 和 PostgreSQL 启动脚本的默认宿主端口，修正启动输出、README、部署说明及原型链接。保留显式端口覆盖能力；容器内部监听端口与 Vite 开发端口不属于本单的对外入口统一范围。

### Acceptance criteria

- [ ] 两套部署分别启动时默认从 18085 提供正式页面、静态资源、健康检查和认证 API，登录与下载正常。
- [ ] PostgreSQL 包装脚本、Compose 默认值和实际输出一致；现有 `CODEXPLOIT_PORT` / `CODEXPLOIT_PG_PORT` 覆盖继续有效。
- [ ] 两套部署同机并存时，第二套端口冲突明确报错并提示使用覆盖参数；不静默换端口，也不停止已有实例。
- [ ] 升级配置保留原数据卷、账号、加密模型设置、任务与产物。独立验收环境分别演练 SQLite / PostgreSQL 重建后的可读性。
- [ ] 用户面向的默认部署链接不再混用 18080 / 18095。源码分析测试中作为目标代码的端口字面量不做无关替换。

### Blocked by

None - can start immediately.

## S02 — 创建项目时上传 ZIP / TAR 源码并生成固定快照

### What to build

**类型：AFK。用户故事：** 用户选择“本地代码 → 上传压缩包”，导入源码后直接进入真实项目和快照；远程 Git 仍通过同一创建入口可选。

支持 `.zip`、`.tar`、`.tar.gz` / `.tgz`，通过受认证、项目隔离的导入过程流式接收与校验，安全展开到隔离暂存区。成功后以不可变导入引用登记代码源并生成真实快照，复用图谱 / 任务流程。创建过程中失败时保留明确可重试的项目状态；不把只建好空项目显示为已就绪，不要求用户重新输入重复信息。

### Acceptance criteria

- [ ] 正式创建表单提供“本地代码 / 远程仓库”；本地选择压缩包后弹出上传界面，支持上述四种扩展名、进度、取消、错误反馈与明确的完成条件。
- [ ] 服务端校验真实格式，拒绝损坏 / 加密 / 不支持的归档；不凭扩展名或浏览器 MIME 判断安全。RAR / 7z 等格式明确提示暂不支持。
- [ ] 解包拒绝绝对路径、路径穿越、Windows 盘符 / UNC 路径、规范化后重名、文件目录冲突、符号 / 硬链接、设备 / FIFO 等特殊文件；不保留归档中的特权位或所有者。
- [ ] 对上传字节、实际展开字节、单文件、文件数、深度和处理时间分别设限；不递归展开嵌套压缩包。超限、CRC / 摘要错误和磁盘写入失败均不发布可用快照。
- [ ] 默认排除 `.git`、生成目录和明确敏感文件类型，显示被排除项及限制；归档原始包仅在有界暂存阶段存在，失败 / 过期后清理，不作为未经筛选的长期源码产物保留。
- [ ] 单一外层包装目录可确定性识别；多根归档保持共同根，不猜测丢弃源码。最终相对路径、内容摘要和覆盖信息可查看。
- [ ] 导入完成后正式页面可查看快照、构建真实图谱并创建任务；重新上传创建新版本，不修改旧任务输入。服务重建后原快照与产物仍可读。
- [ ] 上传 / finalize / 取消 / 查询使用认证 API；覆盖项目隔离、重复提交幂等、并发 finalize / 删除、失败清理、重启中断和 Memory / SQLite / PostgreSQL 持久化。
- [ ] 至少各一份 ZIP、TAR、gzip TAR 在独立 Docker 环境从正式页面完成上传至真实快照和任务；恶意归档合成样例验证服务端拒绝。

### Blocked by

None - can start immediately. S01 可独立交付；本单复用既有代码源、快照和 ArtifactStore。

## S03 — 创建项目时选择 Mac 本地目录并上传源码

### What to build

**类型：AFK。用户故事：** 用户选择“本地代码 → 选择目录”，在 Mac 系统选择器选中目录后，查看文件数量与大小并上传，无须手动打包或填写容器路径。

通过浏览器目录选择能力读取文件和相对路径，复用 S02 的导入生命周期、限额、不可变引用及快照发布。按文件流式上传并限制并发，不将整棵目录或整个压缩包一次性装入浏览器内存。此入口为一次性上传；原目录后续修改需再次选择并上传。

### Acceptance criteria

- [ ] 正式项目创建及项目内新增代码源使用同一入口，Mac Safari / Chrome 可选择目录，保留嵌套目录与中文 / 空格文件名。
- [ ] 上传前展示筛选后的文件数、总大小和排除提示；客户端在传输前过滤明确敏感文件与忽略目录，服务端对收到的相对路径、类型和限额再次验证。
- [ ] 不提交宿主绝对路径；服务端不信任浏览器提供的相对路径，拒绝越界、重名及与归档导入相同的冲突路径。
- [ ] 页面显示进度并支持取消 / 失败后重试；取消选择、空目录、全部被过滤或不支持目录选择的浏览器给出明确提示。旧浏览器可选择压缩包入口。
- [ ] finalize 核对本次收到的文件清单、数量、大小和内容摘要。文件读取失败、缺失或变化时拒绝本次完成；页面明确这是本次上传所读字节的固定副本，不声称是文件系统原子快照。
- [ ] 本地修改不影响旧快照；再次上传形成新快照，新任务可以选择新输入，旧任务与证据继续使用原内容。
- [ ] SQLite / PostgreSQL 分别验证项目、导入来源与快照重启恢复；浏览器验收真实目录上传、取消、限额错误与任务创建，文件系统 / 生命周期回归通过。

### Blocked by

- S02 — 复用已交付的导入生命周期、认证协议、持久化与快照发布。

## S04 — 可选：Mac 本地连接器按需只读挂载并采集固定快照

### What to build

**类型：HITL。用户故事：** 对较大或反复使用的本地目录，用户可通过明确安装和配对的 Mac 连接器选中目录，由受控采集容器只读读取，随后在 Web 应用中使用固定快照。

本单以本机 Docker Desktop 为范围。先完成人工架构评审，再交付本地选择器 → 有效期与项目绑定的授权 → 临时采集容器 → 固定导入引用 → 任务创建的完整路径。主 Web 应用和插件不持有 Docker socket；Docker 操作仅由单独受信宿主组件执行。宿主组件本身仍有较高权限，不能因接口受限而宣称其失陷无风险。

### Acceptance criteria

- [ ] 人工批准安装方式、宿主组件的权限边界、配对信任、目录授权与撤销模型；默认关闭，没有连接器时清楚提供上传入口。
- [ ] 授权绑定具体项目、目录和过期时间；本地原生确认后才建立，网页不能通过任意路径字符串授予自身权限。防止 CSRF、DNS rebinding、重放与跨项目滥用。
- [ ] 仅允许指定摘要镜像、固定 entrypoint、只读源码、禁用网络和受限资源的临时采集容器；拒绝可配置镜像、命令、特权模式及额外挂载。
- [ ] 不挂载整个用户主目录、根文件系统或 Docker socket 给 Web 应用 / 插件 / 采集容器；实际选择目录存在与归属可验证，不跟随越界链接，处理检查与使用之间的替换竞态。
- [ ] 选目录不重建主应用、不影响已有任务。撤销、超时、取消、断连和宿主重启后清理临时容器 / 句柄，旧授权不可继续使用；审计信息不暴露宿主个人路径。
- [ ] 采集后生成不可变导入与真实快照，已有任务不继续读取活动挂载；原目录变化按既有 `source_changed` 语义拒绝，不能发布混合版本。
- [ ] 浏览器电脑与 Docker 宿主不同、Docker Desktop 不可用、目录未授权等情况明确拒绝；不宣称支持远程 Docker 或自动持续同步。
- [ ] 在隔离 Mac 环境完成人工安全与生命周期验收；与 #21 的受控容器权限模型协调，避免重复开放宿主控制入口。

### Blocked by

- S02 — 复用固定导入引用与快照发布。
- 人工批准本单及宿主连接器信任方案。#21 为关联设计参考，不是本单的硬依赖。
