# 插件互操作与虚拟化漏洞验证：Issue 拆分草案

> 本草案保留最初拆分历史；2026-10-21修订后的#28–#36正文与 [当前实施索引](interaction-issues.md)优先，PG为唯一新业务维护后端。

状态：已由用户确认，并于 2026-10-19 发布 GitHub Issues #28–#36。实际编号与依赖见[发布索引](plugin-verification-issues.md)。

来源：本次会话提出的各阶段插件接口，以及漏洞验证所需的环境供应、验证工具、生命周期与证据兼容需求。

## 现有边界与复用

- 已有插件目录、不可变版本、进程协议、标准产物、工作流、知识发布、发现分组和固定报告，不重新建设。
- `verify.Environment` 已有声明性限制，`verify.Executor` 已有执行接口；尚未提供完整环境供应生命周期。Agent 与验证器仍是各自领域接口，不能假设已经实现通用插件协议。
- 现有 #21「通过受控容器 Worker 执行扫描插件」负责工具容器，不负责运行被审计程序。复用其受控 worker 与能力验证，本草案不修改该 Issue，也不复制其实现任务。#21 自身依赖 #19。
- 清单允许 container / remote 不等于已有实际执行支持；能力必须由真实供应器兑现。
- 下列 V01–V09 保留为已批准草案编号；GitHub 正文已使用真实 Issue 引用，映射见发布索引。

## 共同交付约束

- 每单交付可独立演示的真实行为，包含版本化 Schema、领域逻辑、认证 API、正式 UI、持久化、文档及验收；底层接口不能单独作为完成条件。
- 兼容现有 API、插件版本、计划、产物与证据 ID。新增契约采用明确版本和迁移策略，不修改已发布版本的字段含义；新计划不得替换旧 pin。
- Memory / SQLite / PostgreSQL 的支持边界明确，已有完整部署不能静默失去能力；真实环境与 worker 集成必须使用真实后端验收，不能以 mock 证明隔离。
- 静态扫描保持不执行目标 build/test/hook；构建、安装依赖、运行目标、动态验证分别使用明确授权。动态审批绑定规范化计划摘要、源码与环境摘要、目标及权限，不能由插件或模型自报批准。
- Agent 无基础设施管理凭据、任意 shell 或宿主管理 socket。凭据仅使用引用和短期注入，不进入清单、事件、日志或报告。
- 有效权限为清单、安装授权、任务策略与实际可强制能力的交集。插件自身 runtime 与目标环境 backend 分开建模。
- 观察与最终裁定分离；宿主验证证据后派生状态。未复现、超时、环境故障、能力不足不能自动判为 refuted；退出码为零或文本匹配不能单独证明漏洞成立。
- 相关公开边界按 TDD 逐项 red → green，新边界依技能确认；遵循 AGENTS.md 的竞态、稳定性、lint、契约、前端测试/构建与文件系统/生命周期压力测试要求。Go 单元测试兼容三 OS；真实外部后端测试提供隔离入口并明确平台前提。
- 不提交敏感信息、实际环境数据、凭据文件或私钥。AFK/HITL 描述实现所需决策，不改变提交及 push 授权。

## V01 — 在插件中心和工作流编译时核验版本化能力与输入输出契约

**类型：AFK**

**用户故事：** 管理员能看清解析、语义、扫描、路径、Agent、验证和报告能力是否真实可用；编排者在运行前发现不兼容连接。

### What to build

在既有目录、宿主和编译器上扩展可演进的能力及类型契约，区分协议版本、插件包版本、产物 Schema 和执行能力。已有内置 Go 链路及真实进程扫描器通过同一核验流程展示、编译和运行；尚无适配器的能力诚实显示不支持。为后续环境供应与验证预留版本化领域协议，不把所有领域强塞成同一 Execute 方法。

### Acceptance criteria

- [ ] 标准说明覆盖源码接入、解析、语义、扫描、路径增强、Agent、环境供应、验证、报告各环节的输入输出；新增类型通过受控命名空间及本地 Schema 登记，未知类型拒绝且不触发网络解析。
- [ ] 公共清单及目录 API、持久化与正式插件页展示声明/安装/实测可执行能力及不支持原因，插件 runtime 与 environment backend 明确区分；Schema 不能凭字段声明授予权限。
- [ ] 工作流编译检查类型、Schema 版本、直接 producer、scope、包摘要和能力要求；缺少适配器、握手不兼容、含歧义输入时在运行前拒绝。
- [ ] 内置解析→语义→路径与真实扫描器均可从正式页面编译并执行；旧清单、旧固定计划及历史产物可读，新增版本不覆盖旧 pin。
- [ ] 原始报告到标准事实的映射说明 canonical ID、规则身份、覆盖、局限及来源；不同工具对同一事实的冲突观察保留，不能静默覆盖。
- [ ] 目录/编译 API 与真实执行的契约、权限、项目隔离、兼容及页面验收通过，并更新插件接入文档。

### Blocked by

无新增阻塞；复用已完成 #6、#9、#12。

## V02 — 在自定义工作流中执行可追溯的路径筛选与评分增强插件

**类型：AFK**

**用户故事：** 审计者可以在路径发现之后加入独立增强工具，筛选重点路径，并解释每条路径为何保留或过滤。

### What to build

交付一个真实、确定性的路径过滤/评分插件，从固定知识视图及明确上游 discovery.paths 读取输入，输出标准路径与选择说明，在正式工作流中串接到发布和候选分析。插件可通过受控查询适配器补充已存在的代码事实；后续第三方路径工具复用该契约。

### Acceptance criteria

- [ ] 明确输入原始路径、快照/图层 pin、过滤配置与预算，输出保留原路径 ID 和增强 lineage、评分特征/权重版本、保留/过滤原因及覆盖截断。
- [ ] 正式工作流页能加入增强节点，任务详情可对比输入/输出与筛选原因；发布和分析实际消费选定增强节点的结果，不能重新使用 latest 或未选分支。
- [ ] 有界 host.graph.query 或等效适配器限定固定视图、任务 scope、只读查询和预算，不向外部插件开放任意数据库查询或宿主文件路径。
- [ ] 不能伪造端点、证据或调用步骤；call_reachability/hypothesis 不得提升为 taint_flow/verified；无规则路径不得按标题合并进发现组。
- [ ] 重试幂等、跨快照输入拒绝、缺失证据、预算截断、取消迟到结果及重启后 lineage 一致均有真实执行测试；文档说明新路径工具接入方式。

### Blocked by

- V01。

## V03 — 在候选详情生成并审批绑定环境要求的固定验证计划

**类型：AFK**

**用户故事：** 审计者在执行前能查看将验证什么、在哪里运行、需要哪些权限，并批准精确的验证计划。

### What to build

从现有 hypothesis/finding 入口保存并预览版本化验证计划，将 EnvironmentSpec、授权范围和工具能力要求纳入固定输入。扩展已有计划/审批机制，提供正式页面及认证 API；本单完成计划与审批闭环，不宣称已执行动态验证。

### Acceptance criteria

- [ ] 计划明确假设、快照/知识 pin、验证器版本、预期与反证条件、结构化断言、环境要求、资源、预算及局限；允许人工提供经校验的显式计划，不要求自动生成 PoC。
- [ ] EnvironmentSpec 描述 OS/架构、供应器能力、模板/输入摘要、独立服务角色、就绪探针、网络规则、只读快照与 scratch、TTL、权限和凭据引用；不支持字段不能被静默忽略。
- [ ] 原有 API/计划保持兼容；新增规范化摘要覆盖全部执行语义，审批绑定计划、环境要求、源码、目标、权限、期限和可信主体。改变任何相关内容后旧审批失效，不能沿用原计划哈希。
- [ ] 页面区分待审批/已批准/拒绝/失效/不支持；reader 只能查看，writer 提交，审批按可信主体权限校验，模型和插件不能自报批准。
- [ ] 固定计划及审批可重启恢复；并发更新、跨项目、审批重放、过期及权限扩大拒绝有 Memory/SQLite/PG 和认证 API 验收。

### Blocked by

- V01。

## V04 — 通过环境供应插件创建并销毁真实容器验证环境

**类型：AFK**

**用户故事：** 管理员可以选择已授权环境模板，创建受控环境、执行无目标代码的诊断探针、查看实际限制并销毁环境。

### What to build

复用 #21 的受控 worker，新增与扫描插件分离的 EnvironmentProvider，交付一个真实容器供应适配器。正式环境页贯通创建、状态、只读快照输入、受控探针、证据采集和销毁，并将实际施加的限制保存为 EnvironmentReceipt。

### Acceptance criteria

- [ ] 版本化协议实现 DescribeCapabilities、ValidateSpec、Provision、Inspect、RenewLease、Exec/StartService、Collect、Destroy、Reconcile；Reset 可声明不支持。Provision 返回异步操作 ID，命令与服务操作使用结构化参数及服务角色。
- [ ] 创建请求幂等且绑定 scope、模板摘要和请求摘要；返回有限权限环境句柄，不暴露宿主路径、基础设施密钥或管理 socket。
- [ ] 凭实际 worker 能力强制源码只读、scratch、CPU/内存/进程/磁盘/期限及网络策略；不满足要求返回 unsupported。Receipt 同时记录 requested/applied、供应器/模板版本、实际镜像摘要、worker 和环境 ID。
- [ ] 认证 API 与正式 UI 完成真实创建→就绪→只读诊断探针→日志/测试产物→销毁，reader/writer/admin 权限和项目隔离明确；本单不授权执行目标仓库代码。
- [ ] 正常、创建中失败、取消、超时均进入清理，Destroy 幂等；环境状态与清理状态分开记录，失败不能虚报已销毁。
- [ ] 独立 worker 实测资源/网络/文件访问限制、损坏产物、重复请求和迟到写入拒绝；持久化与重启读取、部署文档及页面验收通过。跨 worker 重建回收由 V07 扩展。

### Blocked by

- V01、V03。
- #21 — 通过受控容器 Worker 执行扫描插件；继承其 #19 依赖，不重复建设 worker。

## V05 — 在授权容器环境验证单服务候选并基于真实证据派生裁定

**类型：HITL**

**人工节点：** 评审并验收动态执行的独立授权边界、模板来源、worker 信任与测试目标范围；这不是对现有静态扫描权限的隐式扩大。

**用户故事：** 审计者对指定固定快照的候选发起验证，能追溯构建、启动、测试、断言、证据及最终结论。

### What to build

新增验证工具领域适配器，通过 V04 环境句柄执行 V03 的已批准计划。以合成单服务仓库完成真实构建/启动、就绪检查与结构化验证，贯通任务、假设、环境、验证运行、证据和 finding；保持现有 DeriveOutcome 宿主裁定权。

### Acceptance criteria

- [ ] 验证器提供 ValidatePlan、Execute、GetStatus、Cancel、CollectEvidence 或等效领域端口，并经能力握手安装；旧 verify.Executor 可由适配器复用，不假设已实现通用 JSON-RPC。
- [ ] build、安装依赖、运行目标及动态验证分别授权，源快照不修改；构建写入独立工作副本，依赖/镜像固定摘要，构建阶段和运行阶段网络分别配置并记录。缺失环境或未授权操作在产生副作用前拒绝。
- [ ] 工作流能编译固定验证资源与步骤，从明确候选/假设及已批准计划启动；正式任务/候选页也可显式发起，未批准时停在待审批而非伪装成功，失败/取消进入 finally 清理。
- [ ] 验证器输出带步骤 ID 的结构化观察、控制组/断言、复现步骤、退出码、时序及证据引用；宿主检查 schema、来源、摘要、scope 和语义后派生结论，退出码/文本匹配不能单独确认漏洞。
- [ ] 合成样例覆盖真实复现、有效反证、证据不足、目标未就绪、缺依赖、超时、取消及不支持：只有满足复现证据条件才 confirmed；未复现不能 refuted，环境失败明确 blocked。
- [ ] 产物、运行及候选裁定一致持久化，迟到结果不能覆盖取消/租约栅栏；既有人工裁定和严重性审计不被静默覆盖。Memory/SQLite/PG、真实 worker、认证 API、任务/候选页面及文档验收通过。

### Blocked by

- V03、V04。

## V06 — 验证带数据库依赖的多服务目标并恢复已知基线

**类型：AFK**

**用户故事：** 审计者可以验证依赖数据库的应用，并保证重复验证从相同测试数据和网络拓扑开始。

### What to build

在既有真实验证链路上增加目标、测试驱动和依赖服务的角色拓扑，以及可声明的基线恢复能力。用合成应用与数据库完成服务级网络控制、就绪检查、初始化及第二次运行的一致性演示。

### Acceptance criteria

- [ ] EnvironmentSpec 支持固定摘要的目标/依赖/驱动角色、内部服务发现、角色级连通规则、入口/出口策略和就绪/存活探针；无公网出口不妨碍明确授权的内部连通。
- [ ] 数据库等依赖使用测试数据和临时凭据，凭据经引用定向注入，不进入明文事件/证据；页面显示服务拓扑、就绪失败位置、网络策略及基线标识。
- [ ] 支持的供应器实现 Reset 到明确基线并返回新 receipt/执行标识；不支持时销毁重建，不跨候选复用脏环境。任何复用必须匹配基线、配置与授权范围。
- [ ] 合成应用完成两次独立验证，初始化数据与基线一致；依赖失败、服务超时、重置失败、中途取消和配置变化有真实后端测试，清理覆盖全部服务/网络/卷。
- [ ] 报告输入可读取完整 receipt、服务摘要和基线引用，未满足系统/内核/依赖要求时明确记录局限并拒绝声称精确复现；多服务文档、认证 API 与页面验收通过。

### Blocked by

- V05。

## V07 — 重启或 worker 失联后回收验证环境并拒绝旧执行结果

**类型：AFK**

**用户故事：** 服务或 worker 崩溃后，管理员能看到环境是否仍存在、清理是否成功，并安全重试未完成验证。

### What to build

在 V04 的单次资源生命周期上完成数据库租约、单调 epoch、Reconcile、TTL 回收和独立清理状态，使双应用/worker、断连和重建下的验证与资源不泄漏、不重复提交。正式页面展示清理告警、重试及最终回收结果。

### Acceptance criteria

- [ ] 数据库保存环境 ID、provider、worker、scope、资源所有权标签、lease/epoch、TTL、运行状态和 cleanup 状态；PG 双 worker 以数据库时钟与栅栏拒绝重复拥有及迟到结果。
- [ ] 幂等 Provision/Destroy 处理中途响应丢失；Reconcile 按持久化身份和资源标签核对，不误删其他任务/项目资源，创建记录缺失的孤儿也有有界处置策略。
- [ ] 断连停止领取与续租，超时资源由独立回收路径处理；租约过期时主动终止旧环境活动，不能只拒绝结果却让测试继续运行。
- [ ] 默认不续跑未知执行进度的动态步骤：标记 interrupted，回收并从已知基线创建新 attempt；只有供应器声明且证实可恢复时才恢复。保留旧证据、幂等语义及审批有效性校验。
- [ ] 验证结论与清理状态独立；清理失败明确告警，可重试、可审计且有 TTL 最终回收，不能清除运行历史伪装成功。
- [ ] 正式 UI、认证 API、真实 worker/PG 覆盖双 worker、应用/worker 硬停、数据库断连、创建/销毁响应丢失、重启、跨项目以及孤儿回收；运行完整生命周期压力测试。

### Blocked by

- V05。

## V08 — 用第二种虚拟机供应器复用同一验证工具完成真实验证

**类型：HITL**

**人工节点：** 确认可用虚拟化平台、宿主/worker 条件、模板来源与许可，以及需要支持的 OS/内核能力，再选择一个真实 VM 后端。容器不能冒充虚拟机支持。

**用户故事：** 需要特定系统或内核的验证可选择真正的虚拟机环境，已有验证工具、证据和报告接口保持复用。

### What to build

为已选定的一个真实 VM 后端实现 EnvironmentProvider，并使 V05 的同一验证工具通过能力协商运行。通过第二种后端验证环境协议的可替换性，不在本单要求同时支持所有虚拟化产品。

### Acceptance criteria

- [ ] 选定平台及最小支持矩阵记录为架构/部署决策；安装、worker 权限和可信模板可审计，不向应用、Agent 或验证插件提供基础设施管理凭据。
- [ ] 实现创建、就绪、受控命令/服务、日志采集、取消、销毁、租约和回收；Reset/快照回滚可选，缺少能力时重建，不以空实现返回成功。
- [ ] receipt 记录实际 OS/架构、内核、VM 模板及磁盘摘要、供应器版本、网络与配额；所需能力不匹配时在执行前拒绝。
- [ ] 正式 UI 能选择容器或 VM profile 并显示真实能力；同一验证工具与结构化断言在两个后端运行合成样例，验证结果、证据来源及环境差异可比较。

## V09 — 固定报告展示验证环境、结构化断言与完整证据链

**用户故事：** 报告读者能判断漏洞在什么环境、基于什么断言与证据得到结论，并看到未验证部分和环境清理情况。

### What to build

扩展已有报告固定输入与三种输出，从真实验证运行采集计划、审批、environment receipt、构建/服务/基线、步骤观察和证据；正式报告页可追踪回候选、工具调用与环境，历史报告不因环境销毁或后续裁定变化而改变。

### Acceptance criteria

- [ ] Markdown/JSON/SARIF 固定验证计划与环境/工具摘要、执行 attempt、步骤断言、复现步骤、支持/反对/未决证据、限制及采集时的 cleanup 状态；审批仅显示必要审计信息，不输出凭据或个人信息。
- [ ] 报告绑定生成时的证据和 receipt 产物，不读取已销毁环境或 latest 替换旧输入；运行后清理变化不改写历史报告，页面当前状态与报告固定状态明确区分。
- [ ] 环境声明和实际能力差异明确显示；缺失/损坏/跨快照证据、无法支持的 confirmed/refuted 或采集中变化拒绝生成，环境故障和未复现不混同已排除。
