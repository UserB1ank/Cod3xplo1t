## 2. 不再讨论的产品决策

- 新项目=一份源码的一次审计；创建时内部保存输入，无独立快照按钮，无“更新代码”。名称说明可编辑，另一份代码另建项目。旧多输入项目保留。
- 创建后点击一次“开始图谱化分析”，传统工具自动执行代码图谱→安全语义/攻击面→候选路径→筛选评分。可选Agent辅助不阻断默认无模型执行。
- 完成后可从入口查看1–2跳局部图，按需展开和查看源码；路径有来源/理由/证据等级，不能把调用链当污点链。
- 工作台默认主Agent自由对话，模型自主选MCP工具；禁止intent枚举、关键词路由、固定三类指令、固定工具链替代模型选择。
- 主Agent可补路径、派子任务、发纠正消息；宿主管范围、权限、预算、并发、租约、进程和证据。直接人工干预和全局暂停/停止始终可达。
- 方向消息需要真实接收/应用回执；停止需要执行器确认/栅栏，不是前端改状态。普通已授权动作无需逐轮审批，动态验证等额外授权仍按原领域流程。
- 候选/确认、优先级/严重度、阶段完成/run结束/覆盖达标分开。新路径产生账本修订，旧报告固定。

## 4. 每单的开发动作

1. 读取当前Issue与评论、AGENTS.md、相关契约/服务/现有测试。确认Issue仍开放、阻塞已解除，不重做已关闭任务。
2. 对照原型梳理公开输入/输出、scope、错误和恢复边界。按仓库TDD规则确认新测试边界，再逐个red→green；已确认产品方向无需重复问。
3. 复用现有领域服务，补必要PG迁移、版本化DTO/Schema与样例、认证REST/MCP、UI和有序事件。迁移号从当前目录取下一可用值，不在计划里硬占。
4. 真实后端接线后删对应页面示例数组/定时器。无能力、无模型、预算失败、部分覆盖、未知、取消不回退原型成功。
5. 按本单范围运行测试，完成真实PG/执行器与浏览器验收；在交付说明区分脚本provider、合成fixture和真实模型证据。
6. 检查差异/隐私，更新AGENTS完成记录；按用户已授权Issue交付流程独立commit、关闭对应Issue，再推进未阻塞任务。没有用户明确push要求就不push。修文档/准备计划不冒称功能Issue已验收。

## 5. 开发验收命令与证据

以下是**后续实现的交付门槛**，不是本轮文档修订已运行的测试结果：

```bash
make test
make lint
make check-contracts
make test-postgres
make test-web
npm --prefix web run build
```

文件系统、进程、消息生命周期或恢复变更还跑`make test-stress`。Go测试必须兼容CI三OS；PG集成提供隔离环境。模型测试先用合成provider/MCP验证配对/权限/故障，再在既有授权与预算内做真实模型最小验收，不能只用固定脚本证明模型自主选工具。

浏览器验收至少涵盖：创建→ready→四阶段（无模型默认成功）→入口图谱→路径→开放会话纯问答/真实工具→新增路径→子任务→纠正消息→暂停/继续/停止→重启→覆盖/报告。按Issue切片验收相关子链，最终再串联。
